## 3. История Supabase и что осталось нерешённым

### 3.1 Восстановленная исходная база

Проект-источник: `https://uhtrklxakbomwuqnegea.supabase.co`. Исторически в восстановленной базе подтверждены `public.unfallatlas`, `unfallatlas_partitioned`, 16 `unfallatlas_uland_01..16`, PostGIS, индексы, grants и RLS. Набор — 269 048 ДТП 2023 года. Земельные таблицы были прикреплены к родителю как партиции.

По старому дампу партиционирование/ATTACH PARTITION существовали уже до восстановления. Поэтому версия «восстановление превратило standalone-таблицы в партиции» не подтверждается.

Прямой endpoint дочерней `unfallatlas_uland_12` возвращал `404 PGRST205` (не найден в schema cache), а parent с `uland=eq.12` — 200. Историческая проверка исходников PostgREST 12.2.3 / 13.0 / 14.5 показала исключение `relispartition` из экспонируемых relations. Это объясняет REST-недоступность дочерней партиции при существующей PostgreSQL-таблице. Обычный view над ней был доступен. Пользователь не принял 16 views как способ непосредственного обращения к физическим таблицам.

Не доказано, почему прежний живой API когда-то принимал прямые имена при такой структуре дампа. Git не хранит полной тогдашней схемы/настроек API. Не придумывать ретроспективную настройку, которая якобы всё объясняет.

### 3.2 Ошибки 500 / 57014

Реальный ошибочный запрос: parent, `select=oid,xgcswgs84,ygcswgs84`, `uland=eq.5`, `order=oid.asc`, `offset=0`, `limit=20000`, `Prefer: count=exact`. Ответ — `canceling statement due to statement timeout`, code 57014. Аналогично земли 03/08/09; крупные земли чаще не завершались.

Исторические настройки: anon statement_timeout=3s, authenticated=8s, authenticator=8s и lock_timeout=8s. SQL Editor под другой ролью сам по себе не доказывает timeout роли браузерного API. Пользователь сообщил Nano и график CPU <1%; это не измерение ресурсов ровно внутри сбойного интервала.

Max Rows в разных фазах менялся: первоначально фактическая страница ограничивалась 1000, позже 20000; пользователь затем сообщил 60000. Эти значения относятся к разным моментам. Последнюю текущую Dashboard-настройку старой базы 12 октября не перепроверяли. Max Rows — лимит ответа, а не продолжительности SQL.

Планы для земли 05: 59 640 строк, seq scan одной партиции, сортировка oid с external merge около 2 МиБ на диск; простой select около 53.6 мс, отдельный count около 13.5 мс. API-подобный агрегирующий запрос в разных прогонах — около 69–867 мс. Generic plan с runtime pruning убирал 15 под-планов и выполнялся около 102 мс; прямой запрос к дочерней таблице около 94 мс. Эти хорошие отдельные планы не воспроизвели состояние именно в момент таймаута.

В снимке pg_stat_activity было около десяти одновременно активных authenticator/PostgREST 14.5, без blocking_pids, без wait_event. Он не доказывает, что блокировок/нагрузки никогда не бывает. RLS SELECT USING(true) на parent/дочерних таблицах не дал свидетельств тяжёлой вычисляемой policy.

Наблюдение «первая серия после паузы иногда падает, повторные проходят» воспроизводилось, но механика прогрева не установлена. Без exact count были успешные прогоны; с count тоже были успешные, а один получил 57014. Все успешные полные серии давали 269 048 уникальных строк, без несогласованности чисел по землям.

**Вывод:** серверный SQL timeout установлен; холодный кеш, ресурсы Nano, планы/пул, одновременная работа, exact count и форма запроса — рассматривавшиеся факторы, не доказанная единственная причина. Не утверждать, что «общая таблица плохая», «RLS виноват», «4 задачи вылечили» или «индексы отсутствовали». Повторение после пауз само по себе ответа не даёт.

## 4. Новый самостоятельный Supabase-эксперимент

Проект: `https://fiambamorokfphkzdjxc.supabase.co`. Создан отдельный checkout UAD от 457de74, перенесены исправленные фильтры. Новый импорт выполнен в отдельную базу, старый источник не заменён.

### 4.1 Импорт и схема

Экспорт источника сохранён в `UAD_data/transfer`: 16 JSON, CSV, manifest и verification.json. Импорт одной транзакцией: 16 **standalone** таблиц без parent/ATTACH, 269 048 строк, 14 исходных полей включая geom. PostgreSQL 17.11, PostGIS. На каждой: PRIMARY KEY oid, CHECK uland, индексы geometry/category/weekday, RLS SELECT policy `public_read` для anon/authenticated с USING(true).

В браузере достаточно VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY/publishable key для разрешённого REST-чтения. Для создания таблиц/импорта через PostgreSQL использовалась отдельная рабочая строка подключения; публичный браузерный ключ не заменяет это подключение. Пароль не должен становиться VITE-переменной или частью публичного бандла.

### 4.2 Исправления загрузчика

- Прямые `unfallatlas_uland_01..16`, без parent/views.
- Две фазы: координаты для карты, затем необходимые атрибуты; это относится к Supabase-версии, не файловой.
- Четыре параллельные async-задачи земель. Это сетевой concurrency, **не четыре Web Workers**.
- ORDER BY oid по уникальному индексу; запрашиваемая страница 20 000, offset += фактически полученные строки.
- Даже короткая непустая страница не означает конец: читаем до пустой страницы, чтобы серверный Max Rows не обрезал набор незаметно.
- В загрузке карты нет exact count и нет автоматических retries: ошибки видимы, есть ручной повтор.
- Отмена старого запуска, защита от устаревших callbacks, валидация координат/земли/ID/порядка, merge по land:oid с проверкой пропусков/лишних атрибутов.
- Каждая завершённая земля появляется как точки сразу. Hexagon/Heatmap допускаются после успешных координат всех земель. Частичная ошибка не выдаётся за полную готовность.
- Фильтры доступны после полного merge атрибутов; null=Alle, 1=Mit, 0=Ohne, между участниками AND. Ноль не трактуется как отсутствие условия.

Offset предполагает неизменность набора во время чтения. Две REST-фазы не являются единым согласованным database snapshot. Новый эксперимент одновременно меняет API/проект/схему/индексы/форму count/concurrency; это не чистое причинное сравнение одного параметра.

## 5. Новое направление: файловая карта и аналитика

Пользователь хочет уйти от зависимости карты от паузы Supabase Free и добавить полноценные экраны аналитики вместо одних точек. Решено: небольшие готовые сводки для обзора всех лет; подробные записи только выбранного года; остальные годы лениво, с ограниченным кешем.

Сначала рассматривались два источника Supabase/Parquet под общим интерфейсом. **В текущей реализации единого переключателя backend нет:** legacy index.html использует Supabase, app.html — FileLoader. Общая логика данных/фильтров в рамках файловой версии реализована, унификация обоих backend остаётся возможным отдельным направлением. Не обещать уже работающую двойную версию одной кнопкой.

Были изучены примеры Kyle Barron и пользовательские mobile-network-map / charging-points: Arrow/Parquet, совместная геометрия/атрибуты, упаковка, workers, владение буферами. Наблюдения не дают права называть весь путь zero-copy. Ссылки на исследования: Observable zero-copy-apache-arrow-with-webassembly, geoparquet-on-the-web, geoarrow-and-geoparquet-in-deck-gl; репозитории Kirman442/mobile-network-map и Kirman442/charging-points. Их менять в UAD-задаче не требуется.

### 5.2 Методика и ограничения интерпретации

- Это геокодированные ДТП с пострадавшими; не все полицейские ДТП.
- Категория 1 — число ДТП с погибшими, не число погибших людей. Категории 1+2 — доля ДТП с тяжёлыми последствиями, не доля тяжёлых травм среди людей.
- Флаги участников пересекаются. Одновременно Pkw+Rad не доказывает столкновение именно этих двух; один отмеченный вид не доказывает одиночное ДТП.
- Доступны год/месяц/день недели/час, но не полная дата/минуты. Нельзя восстановить дату из UID или привязать каждый случай к конкретному празднику/погоде.
- ДТП с Pkw на 10 000 Pkw = число ДТП с участием Pkw / ((парк на 1 января Y + парк на 1 января Y+1)/2) × 10 000. Это приближение парка по двум концам, не measured annual mean, не риск поездки и не показатель с поправкой на пробег.
- В Германии опубликованный автопарк включает Sonstige; нельзя молча заменить его суммой 16 земель. При суммировании snapshot сначала выбирается уровень, иначе задвоение subtotal.
- Источник не содержит силовую установку участвовавшего автомобиля. BEV/PHEV парк — региональный контекст, не BEV-specific аварийность. Hybrid включает PHEV: их нельзя складывать как непересекающиеся категории.
- Коды административных районов ДТП и KBA Zulassungsbezirke не считаются уже сопоставленными. Нужен crosswalk, особенно города-земли/объединённые регистрационные округа/изменения границ.
- Для krad/gkfz нормирования сначала согласовать определения числителя и классов автопарка. Освещение/мокрая дорога дают структуру среди зарегистрированных ДТП, не вероятность при езде ночью/в дождь без экспозиции.
- Сезонное/территориальное изменение и корреляция не устанавливают причину. COVID, электрификация, новый дорожный объект требуют отдельной методики/данных.

### 5.3 Parquet / Arrow экспорт

Актуальная папка: `UAD_data/binary-2020-2025-20261011-143536`, generation `404fc8c681334561911392783520c8f2`. 96 год×земля shards, **891 файл** во всех профилях вместе, 605 221 738 байт. Это полный экспериментальный пакет с дублями форматов/архивами; не размер одного production-набора.

Сегодня вновь проверены размер и SHA-256 всех 891 файлов: ни одного несовпадения. Девять объявленных выходов prepared тоже совпали с manifest. Лишний accidents_2025_test.csv не входит в authoritative manifest, не является источником готового набора.

Форматы: Parquet ZSTD3/ZSTD10/Snappy, Arrow IPC file и stream, каждый identity/Gzip/Brotli; row groups/batches 16 384. Внутреннее IPC-сжатие выключено для совместимости Arrow JS 19. Для браузерной карты выбран Arrow file + HTTP Brotli; альтернативный loader использует Parquet ZSTD10.

Runtime geometry = FixedSizeList<Float64,2>, [longitude,latitude], WGS84. Пять знаков после десятичной точки, не Float32. Это примерно метровый уровень, **не сантиметры**; для NRW контрольный max estimated shift около 0.653 м. Полные исходные координаты и служебные поля сохранены в archive/accidents_YYYY_full.parquet. Округление runtime не затрагивает первичный CSV/архив.

Координаты и атрибуты находятся **в одном файле земли**. Текущий loader скачивает и декодирует файл целиком. Отдельной сетевой фазы «сначала координаты, потом колонки» в файловой версии нет; Arrow stream сам по себе тоже этого не гарантирует. HTTP Range/projection/FFI — не выполненные оптимизации. Runtime Parquet не заявлен как стандартный GeoParquet; новые файлы границ имеют отдельную WKB-схему.

Колонки: UInt32 ID, UInt16 год, UInt8 категории/флаги, string UID/геокоды; геометрия Float64. Не смешивать ID/атрибуты в Float32 координатный массив. Автопарк/indicators экспортированы в те же варианты, JSON/CSV analytics скопированы побайтно. Каждый вариант при создании считан обратно с проверкой всех полей/типа/порядка/метаданных, сжатый Arrow распакован и сравнен с исходными IPC bytes.

Лаунчер `RUN_PREPARE_BINARY.cmd` / scripts/run_binary.ps1 работает с соседним UAD_data, создаёт .venv-binary, использует pyarrow==25.0.1, принимает DataRoot/Output/SkipInstall/Python. Результат сначала staging, completed только после полного успеха, существующая папка не перезаписывается. Работает по одному году, без удержания всех шести лет.

### 8.1 Экран обзора

Старт Германия, последний год каталога, выбор земли/года. Динамика, числа/доли последствий, группы участников, сравнение земель, показатель с Pkw/автопарком. ### 8.2 Время и сезонность

Территория, from/to, все ДТП или одна группа участия. Месяцы, profiles будни/выходные, weekday×hour, year×month. Число / среднее на календарный день / доля. Совместный агрегат в исходном HTML около 382 980 байт, не отдельная библиотека запроса произвольных фильтров. Исходный weekday1=воскресенье; визуально Пн–Вс. Знаменатели UTC, високосные годы. Годовая матрица показывает все годы с выделением выбранного периода, не автоматическую аномалию.

### 8.3 Тяжесть и условия

Категории последствий, динамика долей, освещение и покрытие отдельно, их точные совместные сочетания с counts и percentages. Тяжесть — по всему ДТП. Представления структуры и количества различаются. Нет статистического утверждения «ночь опаснее» по одним accident shares.

### 8.4 Карта и фильтры

Один выбранный год, по умолчанию последний в каталоге (2025). Четыре постоянных Web Workers, земля появляется после готового целого shard. Загружается год всех 16 земель; выбор конкретной земли — фильтр загруженного года, не отдельный incremental download региона. Последующие годы по выбору, cache generation:format:year.

Участники: шесть независимых null/1/0, между ними AND. Месяцы/дни/часы/последствия/свет/покрытие — OR внутри списка и AND между полями. Все = отсутствие ограничения, не отдельная категория. Последнее снятое значение возвращает все.

Месяцы 12 и сезоны (зима 12,1,2; весна 3,4,5; лето 6,7,8; осень 9,10,11); дни 7 и будни 2–6/выходные 7,1; четыре периода: ночь 22–05, утро 06–09, день 10–15, вечер 16–21. Пресет заменяет выбор соответствующего поля. Нет автобан/город как типа дороги в данных; покрытие не подменяет его.

Счётчики возле опций используют остальные активные фильтры, исключая своё поле (у участников — только конкретный флаг). Невыбранные нулевые значения disabled лишь после готовности; выбранные можно снять. Пресеты/смена контекста всё же могут дать пустую выборку; показываем честное сообщение/сброс, не подбираем самовольно другие значения.

Workers возвращают Uint8 маску, facets и count; DataFilterExtension скрывает точки по маске. Карта/итог обновляются одним результатом, старые запросы не публикуются, промежуточная очередь объединяется до последнего состояния. Нет кнопки Применить; Esc/клик вне закрывают список.

### 8.5 Карточка и другие ДТП в 50 м

Клик выделяет одно ДТП кольцом. Радиус попадания 6 CSS px, coarse/touch10; при множественном GPU pick — до 8 вариантов, девятый означает «не менее 9», не точный total. Карточка рядом/ниже, лёгкий allowlist DTO примерно 260–264 байта в проверках, без полного массива attributes на main thread.

Поля: год/месяц/weekday/hour interval, цвет/текст последствий, SVG с подписями отмеченных участников («участвовали»), освещение/покрытие, тип/вид сценария, земля и ссылка на координаты OSM. Служебные record_id/source_uid/source_oid/plst/linref не показываются. Полной даты, времени до минуты, адреса и числа пострадавших людей нет. Автогеокодирование не запускается; внешняя карта только по клику.

Esc сначала закрывает фильтр, потом выбор; пустой клик/крестик снимают выбор. Камера его сохраняет. Год/неподходящая территория/исключающий фильтр снимают с пояснением; устаревший ответ не возвращает карточку.

Окрестность считается только после раскрытия по текущему году/территории/фильтрам. Без пространственного индекса: linear scan в workers, bbox → условия → Haversine ≤50 м. Центр — выбранная запись, не клик. Сам record_id исключён; другие случаи в тех же координатах сохраняются. Count точный, ближайшие сначала 20, showmore по 20 до 100, cap явно подписан. Дистанция приблизительная: сферическая формула и округление координат. Пространственный индекс пока сознательно не добавлен. C19 «похожие в районе» — отдельная отложенная аналитика.

### 8.6 Общая оболочка и кеш

AppShell — один корень. NativeMap lazy и после открытия остаётся смонтированным, скрывается на других экранах. Один FileLoader и четыре workers до закрытия корня. На первой загрузке обзора пула workers и полных записей нет. При скрытой карте picking/Esc выключены; геометрия/карточка/камера/filters остаются.

Каждый раздел помнит собственный контекст. Первый визит наследует только территорию и конечный год, не сложную комбинацию участников. Простое меню возвращает собственный выбор. «Показать на карте» явно переносит территорию, end-year, одну группу, сбрасывая только participant conditions; остальные фильтры карты сохраняются, notice предупреждает. Разные числа карты/аналитики при этих дополнительных фильтрах допустимы.

pushState/replaceState/popstate поддерживают Back/Forward без полного reload; sessionStorage uad-shell-v1 + uad-map-filters сохраняет настройки. В рамках жизни root сохраняются scroll/card/camera/binary cache. После полного refresh бинарного кеша уже нет; отдельные legacy HTML имеют свой lifecycle.

100/32 МиБ — LRU учтённых уникальных буферов Arrow в workers, ID/координат и реальных masks, не total memory процесса. Временные decode buffers, GC, WASM, GPU, тайлы, DOM и аналитические агрегаты поверх. Вытеснённый год допустимо загрузить/декодировать заново; URL SHA checksum помогает HTTP cache разделять поколения.

Аналитика пока persistent iframe adapters. Генератор prebuild/predev скрывает дублирующий header/menu исходных макетов, добавляет same-origin bridge. Проверяются sourceWindow/origin/screen/revision; ready отправляет актуальный контекст, stale ответы игнорируются. Профили графиков/прокрутка iframe сохраняются. Они **ещё не переносятся на общий query engine**. Исходные годы fixed2020–2025, при добавлении новых лет нужно синхронизировать агрегаты/шаблоны или завершить native port.

## 12. Что нужно для следующей публикации

### Supabase-вариант

Он уже живой. Нового push/deploy ради факта публикации сейчас не требуется. Если решим обновлять его, сначала определить реальные изменения и release target; не менять базу/timeout/партиции по предположениям. Не смешивать этот релиз с новой файловой архитектурой.

### Файловый UAD preview

Предпочтительный следующий release — отдельный тестовый Netlify-сайт, сохранив существующий Supabase URL, после согласования пользователем. Это предложение, не выполненный деплой.

Необходимая подготовка:

1. Зафиксировать точку входа app.html либо осознанно сделать новый root index/redirect, базовый путь /accidents/ или корень выбранного хостинга.
2. Подготовить publishable dataset subset: не выкладывать все 891 дубликатов/служебные settings/exports. Loader сегодня требует complete catalog/96shards и согласованные paths/profiles, поэтому просто удалить ненужные files из manifest нельзя без проверки datasetSpec. Поддерживаемый небольшой manifest/adapter — отдельная работа.
3. Обеспечить manifest/summaries и нужные shards/overview правильной generation; одновременно опубликовать согласованный набор, не смешивать checksum metadata разных экспортов.
4. Для Arrow+Brotli дать корректный Content-Encoding:br, MIME/CORS при другом origin, checksum после браузерной распаковки. Сама .br extension или успешность другого Netlify-сайта не гарантирует эти headers. Альтернатива — отдельный проверенный клиентский decompressor/uncompressedArrow/Parquet, но нынешний runtime ожидает br header.
5. Локальный binaryAssetsPlugin **не серверный backend deploy** и не копирует внешнюю UAD_data в dist. `npm run build` в одиночку готовит JS/HTML/prototype adapters, не большие data assets.
6. Cache policies: mutable manifest no-store/revalidate, content-versioned shards immutable/совместимый cache, matching generation. Проверить redirects/spa rules не возвращают HTML вместо .parquet/.br, WASM доступен.
7. Для Arrow route из другого origin проверить доступность Content-Encoding клиенту; CORS expose headers там, где требуется. Не менять режим по user-agent без наблюдений.
8. В новой оболочке пока нет обычного видимого переключателя формата: форматы сравниваются в files.html/benchmark; не обещать продуктовый toggle Arrow/Parquet, пока его не добавили по согласованию.
9. До публикации запушить текущую source branch отдельно, не merge master/main; проверить автоматические deployment triggers. Пуш source не равен работающему deployment.
10. Проверить real network (не localhost), cold/repeat, другие годы, abort/error/hash failure,32 МиБ, физический телефон, разделы/back/forward/card/50 м, matching source counts. Отдельно измерить полный startup и память, не только dataset transfer.

Публикация, слияние, изменения базы и замена живого сайта выполняются только после отдельной конкретной команды пользователя. В текущем запросе пользователь попросил подробный отчёт и обсудил деплой вопросом; новый деплой не запускался.
